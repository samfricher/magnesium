# State and evidence

Use one current learner model across conversations. A memory has a title, scope, summary, free-form state_text, optional topics/retrieval_cues/review_note, and current_basis observations. Original events, observations, and revision history preserve the inspectable basis; historical snapshots are not current guidance. Reading or paraphrasing old work creates no new performance or observation date.

## Authoring

Read neighboring current records first. Identity is the same operation and context, not an identical title. Preserve specific strengths, narrow the missing connection, and retain conditions and uncertainty. Describe what was actually observed rather than assigning a fixed mastery label. Questions and self-reports can inform an interpretation without an issued assessment. Known assistance remains explicit; tutor/source text alone cannot establish independent learner work.

Example: earlier work correctly expands binomials; later work struggles to reverse the sum/product relationship. Preserve expansion strength and describe the narrower reverse-direction gap. Subsequent independent factor selection revises the current description rather than leaving that gap active forever. These are policy illustrations, not facts about this learner or live evaluation inputs.

Rewrite the affected record with relevant current_basis and a reason/change_basis. Previous associated support remains inspectable. Keep only a few useful learner terms, cues, and optional flat topic labels; cues cannot invent a weakness. Use no_change for acknowledgments or turns with no new interpretation. An explicit preference can persist; one observed benefit is not a fixed learning-style diagnosis.

## Contradictions and corrections

A learner challenge triggers inspection of the original task, answer, help, and relevant source. Correct a mistaken description from that evidence without requiring another assessment or deletion. If unresolved, flag a review_note and preserve uncertainty. Explicit review_resolution with support/reason is required to clear a note; an editorial rewrite must not silently clear it.

A correct procedure earlier and a misconception later may both be real: describe the conditions and the narrower changed interpretation. A single slip does not establish a durable misconception; repeated relevant errors can strengthen it. Repeated retrieval of an old suspicion adds no evidence. New evidence can disprove it.

Atomic create/revise/retire operations can consolidate local duplicates while explicitly preserving support. No automatic graph-wide cleanup, model-invented score, fixed universal topic list, user annotation requirement, or hidden verifier veto is needed. A per-target course graph in the workspace is structure, not learner state.

## Durable versus session context

Current descriptions hold long-term understanding. A checkpoint holds the current problem, working diagnosis, concise next action, and actual memory IDs/revisions used. Inspect checkpoint_basis before reusing a diagnosis. Changed/retired references or has_review_note require following the supplied next_call for current text, including the full review note; unchanged revisions alone do not resolve a note. Keep task proposals, observed delivery, help, and learner responses distinct. A skipped or replaced task implies no learner failure.

Honor pause/stop immediately. With recording still on, mode:complete_captured may finish an already captured answer without new capture, task creation/change, or reactivation. A checkpoint may preserve the identical existing pending_task, clear it, or be omitted to preserve the old checkpoint. recording_off blocks completion and new observation/checkpoint/note/trace text; it deletes no history. Resume and recording_on are separate. Failed completion leaves stopped work pending; disclose the save limit.
