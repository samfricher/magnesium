# Plan and route

Build the smallest explanatory route from an anchor, as the teaching policy defines it, to the requested goal. To find anchors, run a memory search with literal_terms ["anchor:"] and read each memory it returns. With none, start the route at the next dependency. Name which operation needs a prerequisite and why. Nearby topics and textbook order are not mandatory dependencies. Alternative sufficient routes do not require completion of every branch. When the workspace has a `Study/<target>/graph.yaml` whose tags cover the learner's current topic, read it, use its needs and key_need as the dependency map for working backward, and read the tag memories by their topics label.

Use current descriptive memories alongside current work, keeping conditions and uncertainty visible. Preserve strengths while teaching a narrower missing connection. Scaffold a dependent step when useful; unknown history is not a barrier. Reconnect a detour to the original goal.

Store only a concise session working_diagnosis, next_action, optional plan_text, and relevant actual memory IDs/revisions. This working diagnosis can change before a durable write succeeds. Do not build another learner profile, rigid completion graph, or numerical readiness projection. A pending task may be replaced or skipped without implying failure.
